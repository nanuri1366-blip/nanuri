# [유자를 품은 오란다&까부리] 핵심 운영 및 개발 지침서 (Guidelines)

본 문서는 프로젝트의 지속적인 유지보수와 운영 중 지켜야 할 **절대 원칙 및 중요 지침**을 정의합니다. 모든 작업자와 개발자는 본 지침을 준수해야 합니다.

---

## 1. 랜딩 페이지 독립성 보장 지침 (절대 원칙)

1. **메인 페이지(`app/page.js`)는 순수 소비자 전용으로 유지**:
   - 랜딩 페이지에는 관리자(`/admin`)나 생산자/작업자(`/producer`) 페이지로 통하는 어떠한 링크, 텍스트, 버튼, 아이콘, 팝업 트리거도 절대 노출하지 않습니다.
   - 랜딩 페이지의 모든 구매 유도(CTA) 버튼은 공식 **네이버 스마트스토어**로만 연결되어야 합니다.
2. **랜딩 페이지 코드 보존**:
   - 관리자 및 생산자 페이지 기능 개편 시, 랜딩 페이지의 레이아웃이나 스타일을 임의로 변경하거나 손상시키지 않습니다.

---

## 2. 관리자 및 작업자 페이지 분리 및 보안 지침

1. **URL 직접 접근 방식**:
   - 관리자 대시보드: `/admin` (직접 브라우저 주소창에 입력하여 접속)
   - 작업자 대시보드: `/producer` (직접 브라우저 주소창에 입력하여 접속)
2. **비밀번호 게이트 인증**:
   - 관리자 인증 비밀번호: `yuzu1234`
   - 작업자 인증 비밀번호: `maker1234`
   - 인증 성공 시 `sessionStorage`에 안전하게 보관되며, 브라우저 종료 시 인증이 초기화됩니다.

---

## 3. 데이터 관리 및 하드코딩 금지 지침

1. **모든 비즈니스 데이터는 Supabase DB 관리 원칙**:
   - 원재료명, 규격 단위, 상품 정보, 완제품 구성, 판매 가격 등은 코드 내 하드코딩을 엄격히 금지합니다.
   - 모든 수정 및 추가는 팝업 모달을 통해 이루어지며, 즉시 데이터베이스에 반영되어야 합니다.
2. **오프라인 / 오류 대비 안전망 (Fallback)**:
   - Supabase 네트워크 단절이나 일시적 오류 발생 시, 시스템이 멈추지 않고 브라우저 `localStorage`를 통해 정상 작업이 유지되어야 합니다.
   - 네트워크가 재연결되면 최신 데이터가 동기화될 수 있도록 설계되어야 합니다.
3. **단가 계산기 데이터 연동**:
   - 단가 계산기는 원재료 테이블(`raw_materials`)의 단위당 단가와 실시간 연동되어야 하며, 임의의 고정 계산값을 코드에 포함하지 않습니다.

---

## 4. 재고 변동 및 이력 추적 지침

1. **변경 사유 필수 기록**:
   - 작업자가 생산 또는 재고 조정을 완료하고 [저장]할 때는 반드시 변경 사유(예: 정기 생산, 신규 입고, 불량 폐기 등)를 함께 기록하여 감사 추적성을 확보해야 합니다.
2. **인라인 최근 변경 확인**:
   - 작업자가 재고를 수정할 때 실수를 방지하기 위해, 각 수정 위치 근처에 최근 변동 수치를 바로 확인할 수 있는 UI를 유지합니다.

---

## 5. 배포 및 버전 관리 지침

1. **작업 완료 후 배포 프로세스**:
   - 모든 수정 작업이 완료되면 빌드 테스트(`npm run build`)를 통과한 후 GitHub 저장소(`origin/main`)에 커밋 및 푸시합니다.
   - Vercel 자동 배포가 정상 완료되었는지 대시보드에서 최종 확인합니다.
2. **작업 내역 문서화 의무**:
   - 기능 변경이나 버그 수정이 발생할 경우, 반드시 `docs/WORK_LOG.md`에 변경 내용과 영향도를 기록합니다.
